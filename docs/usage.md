# 使い方(詳細)

[README](../README.md) の「使い方」の詳細(ターミナル表示とブラウザアプリ)。ビルドと書き込みは README を参照。

## ターミナル表示

ファームウェアの出力は USB CDC(仮想 COM ポート)に出る。ターミナルソフトで開く。起動後 3 秒まではターミナルの接続を待つので、その間に開けば初期化のログから見られる。

### PuTTY の設定

- Session: Connection type = **Serial**、Serial line = XIAO の COM ポート(例 `COM7`)。Speed の値は USB CDC なので関係ない(既定の 9600 のままでよい)
- Connection > Serial: Flow control = **None** を推奨
- 色は ANSI 256 色(`ESC[48;5;Nm` など)を使う。PuTTY は Window > Colours の "Allow terminal to use xterm 256-colour mode" が既定で有効
- 出力は ASCII だけ(罫線は `+ - |`)なので、Window > Translation の文字コードの設定に依存しない
- 改行は "\r\n" で届く。Pico SDK の stdio は、USB の出力で "\n" を "\r\n" に変換する設定が既定で有効(`PICO_STDIO_ENABLE_CRLF_SUPPORT` = 1、`PICO_STDIO_DEFAULT_CRLF` = 1、USB 用の `PICO_STDIO_USB_DEFAULT_CRLF` の既定は `PICO_STDIO_DEFAULT_CRLF`。SDK の stdio.h / stdio_usb.h / stdio.c で確認)。PuTTY の "Implicit CR in every LF" は不要
- 1 文字コマンドは、PuTTY がキーを押すたびに 1 文字ずつ送る前提(Serial 接続では既定でローカルの行編集が働かない前提。PuTTY の文書では確認していない)。Enter は不要。Enter を押すまで効かない場合は、Terminal > Line discipline options の Local line editing を Force off にする
- スクリプトなどでログを取る場合は、Pico の USB CDC は DTR が立たないと出力しないので DTR を立てて開く。解析用には `c` でモノクロにする

### 操作キー

| キー | 動作 |
|---|---|
| `h` / `H` | 左右反転を切り替える |
| `v` / `V` | 上下反転を切り替える |
| `c` / `C` | カラー(ANSI 256 色、画面を上書き)とモノクロ(ANSI エスケープなし、流れる)を切り替える |
| `?` | ヘルプを表示する(約 5 秒、または何かキーを押すまで距離画像の表示を止める) |
| `b` / `B` | バイナリの出力に切り替える(ブラウザや記録用。[frame-format.md](frame-format.md))。ターミナルでは読めない文字が流れる |
| `t` / `T` | バイナリからテキストの表示に戻す |

バイナリの出力中は `h` / `v` / `b` / `t` だけが効く(`h` / `v` は反転を変えて状態メッセージを送り直す)。`c` / `?` は無視する。起動ログやエラーはログのメッセージ(種別 2)で送り、ANSI エスケープやテキストは混ぜない。

起動時はカラー表示、左右反転あり・上下反転なし(h=1 v=0。下記「表示の読み方」の向きの確定値)。カラー表示では、起動後最初の描画・`c` でカラーに切り替えたとき・ヘルプの後に、画面全体を消し(`ESC[2J`)、以後はカーソルを左上に戻して(`ESC[H`)上書きする。各行の末尾で `ESC[K`、ステータス行の後で `ESC[J` を出し、前の表示の残りを消す。

### 表示の読み方

モノクロ表示の例(8x8、既定の h=1 v=0。値は `depth_view_render` / `depth_view_render_status` に作ったデータを渡して生成したもので、実測ではない):

```
                           up
       +----------------------------------------+
       | .260 =138 +120 +102 * 84 # 66 % 48 % 30|
       | -160 =142 +124 +106 * 88 # 70 x    % 34|
       | -164 =146 =128 ?    * 92 # 74 # 56 % 38|
  9pin | -168 =150 =132 +114 * 96 * 78 # 60 % 42| 4pin
       | -172 -154 =136 +118 *100 * 82 # 64 % 46|
       | :176 -158 =140 +122 +104 * 86 # 68 % 50|
       | :180 -162 =144 =126 +108 * 90 # 72 # 54|
       |      -166 =148 =130 +112 * 94 * 76 # 58|
       +----------------------------------------+
                           down
[cm] near @%#*+=-: far .=>2000mm x=status ?=sigma>50mm blank=none
frame 123 | temp 31C | zone0 top-right (h=1 v=0)
15.0 fps | read 11.20 ms | draw 3 ms | 452 B/frame
valid 61/64 (x 1, ? 1, none 1) | errors ready 0 data 0
sigma of status-ok zones: median 19 max 80 limit 50 | keys h v c ?
```

- 画面は 8x8 で 17 行、各行は ANSI エスケープを除いて 80 桁以内(PuTTY の既定 80 x 24 に収まる。ヘルプも同じ。テストで最長の値の場合を検査している)
- 各ゾーンは距離 [cm]。モノクロは前に濃淡の文字(近い順に `@ % # * + = - :`、0〜2000 mm を 250 mm ごとの 8 段階。2000 mm 超は `.`)。カラーは背景色(近 = 赤 → 黄 → 緑 → 遠 = 青、2000 mm 超は暗い紫(256 色の 53)。段階 7 の青、無効の灰色と見分けられる色にしている)
- 無効なゾーン: `x` = 測距ステータスが 5 / 9 以外、`?` = ステータスは有効だが sigma が上限(既定 50 mm、暫定)を超える、空白 = ターゲットなし。カラーでは灰色の背景
- 枠の外の目印は、**センサーを自分に向けて、9 ピン列が左・4 ピン列が右になるように持ったとき**の物理的な向き(左 `9pin`、右 `4pin`、上 `up`、下 `down`)。目印は表示に固定で、反転しても動かない。反転で変わるのは、どのゾーンをどこに描くか。ステータス行の `zone0` は、センサーのゾーン 0 を描いている角
- **向きの確定値: 左右反転あり・上下反転なし(h=1 v=0)**(2026-09-27、実機で確認。PuTTY で、センサーを自分に向け 9 ピン列を左にして持ち、表示と見た目が一致した。離れて腕を振ると表示が追随した)。このとき **ゾーン 0 は、センサーを正面から見て 9 ピン列を左にしたときの右上** にあり、表示でも右上に描かれる。既定値は `include/bootcamp_config.h` の `BOOTCAMP_FLIP_H_DEFAULT` / `BOOTCAMP_FLIP_V_DEFAULT`
- ステータス行 1: フレーム番号(1 フレーム目は `(warming up)`。起動直後の 1 フレーム目はステータスが 6 / 13 で無効になる)、センサーの温度、ゾーン 0 の角と反転の状態
- ステータス行 2: 直近 15 フレームの合計時間から求めたフレームレート、`get_ranging_data` の所要時間、前のフレームの描画(文字列の組み立てと USB への出力)の所要時間、1 フレームで読むバイト数(ULD の `data_read_size`)
- ステータス行 3: 有効なゾーン数と無効の内訳、読み出しエラーの累計(`check_data_ready` と `get_ranging_data`)。エラーの行はカラー表示では次の描画で消えるので、累計で分かるようにしている
- ステータス行 4: ステータスが有効なゾーン(sigma で除く前)の sigma の中央値・最大と上限。sigma の上限を調整する目安にする
- 起動時のログはカラー表示の最初の描画で画面から消える。見たいときは PuTTY のスクロールバックを遡るか、モノクロ(`c`)に切り替えてからリセットする(スクリプトなどでログを取る場合も同じ。ただし起動直後はカラーなので、ログには ANSI エスケープが入る)
- 初期化に失敗すると赤 LED が点き、`FAILED: <処理> status=<値> (last_i2c_error=..., i2c_error_count=...)` を 2 秒ごとに表示し続ける。測距が始まると緑 LED が点く
- 起動時のログ(`I2C bus recovery`、`I2C1 ... Hz`、`sensor alive`、`init done in ... ms`、`ranging 8x8 @ 15 Hz, 1 target(s) per zone, N bytes per frame`)は Step 1 と同じ(ターゲット数は 2026-09-28 に追加)。`I2C1 ... Hz` は既定の clk_sys 125 MHz で 399361 Hz(SDK の i2c_set_baudrate の計算: period = (125000000 + 200000) / 400000 = 313 クロック、125000000 / 313 = 399361)。`N bytes per frame` は Step 3 で signal_per_spad と nb_spads_enabled を足したので 8x8 で 972(1 ゾーン 2 ターゲットでは 1548)の見込み([design-notes.md](design-notes.md) の「設計メモ(Step 3)」。上の例の 452 は Step 2 の値)
- `ranging` の行の直前に、センサーから読み返した測距の設定の行(`sensor: mode autonomous, integration 5 ms, sharpener N%, order strongest`)が出る。モードと積分時間は CMake のオプションで変えられる([design-notes.md](design-notes.md) の「設計メモ(測距の設定)」)

## ブラウザで表示する(web/、Step 3)

`web/` は Vite + TypeScript のブラウザアプリ。Web Serial で XIAO につなぎ、測距フレームを 3 つの 8x8 画像、three.js の 3D 点群(Step 4)、LiDAR 風ビューとレクチャー画面(Step 5)で表示する。

### 起動

`web/` で次を実行する(初回だけ `npm install`)。

```
npm install
npm run dev
```

Chrome または Edge で **http://localhost:5173/** を開く。Web Serial は Chromium 系のブラウザで、secure context(https または localhost)でしか使えない。`npm run dev -- --host` で別の端末から `http://192.168.x.x:5173/` として開いた場合は接続できない(記録ファイルの再生は使える)。

| コマンド(`web/` で実行) | 内容 |
|---|---|
| `npm run dev` | 開発サーバー(http://localhost:5173/) |
| `npm run build` | 型チェックの後、`web/dist/` に静的ファイルを出力 |
| `npm run preview` | `dist/` をローカルで配って確認 |
| `npm run format` / `format:check` | Prettier で整形 / 整形済みか検査 |
| `npm run lint` | ESLint(typescript-eslint の型情報付きの規則) |
| `npm run typecheck` | `tsc --noEmit` |
| `npm test` | Vitest(`docs/frame-vectors.json` を読んで COBS・CRC・メッセージ・拒否・ストリームの統計を検査) |

コードを変更したら `npm run format` → `lint` → `typecheck` → `test` → `build` を 1 つずつ実行し、警告なし・全 PASS を確認する。

依存:

- dependencies: three(3D 点群の表示。Step 4。OrbitControls は `three/addons/controls/OrbitControls.js`)
- devDependencies: vite(開発サーバーとビルド)、typescript(`~6.0.2` に固定。typescript-eslint 8.x が 6.1 未満までしか対応しないため)、vitest(テスト)、eslint・@eslint/js・typescript-eslint(lint)、prettier(整形)、@types/w3c-web-serial(Web Serial の型)、@types/three(three の型。three と同じ 0.186 系)

three を入れたことで、ビルドの JS は約 28 kB から約 586 kB(gzip 約 150 kB)に増えた(Step 5 の追加で約 607 kB、gzip 約 157 kB)。three の本体だけで Vite の警告の目安(500 kB)を超えるので、`vite.config.ts` の `build.chunkSizeWarningLimit` を 700 kB にしている(ローカルで使う開発用のアプリなので許容)。

### 接続

1. XIAO を USB でつなぐ(ターミナルソフトで同じ COM ポートを開いていたら閉じる。ポートは 1 つのアプリしか開けない)
2. 「接続」を押し、ダイアログで XIAO のポートを選ぶ
3. アプリはポートを開いて DTR を立て、`b` を送ってバイナリの出力に切り替える。最初の 0x00 までに届いたもの(テキスト表示の残り)は捨てる
4. 画像の左右・上下の反転は、データ源(接続・再生の開始)ごとの最初の状態メッセージでファームウェアの設定(既定 h=1 v=0)に合わせる。以後は画面のチェックボックスで切り替えてよい。状態メッセージが再送されても flags が前回と同じなら画面の設定は変えず、flags が変わったとき(ファームウェア側で `h` / `v` が押されたとき)だけ合わせ直す。反転が変わると、マウスが乗っている位置のゾーンの表示も求め直す
5. 「切断」で `t` を送ってテキスト表示に戻してから閉じる。接続直後の `b` の送信中に押した場合は、`b` の送信が終わってから `t` を送る。`t` は 500 ms 以内に送れなければあきらめ、送れていない書き込みを捨ててから閉じる。ポートを閉じる処理が 1 秒で終わらない場合も未接続に戻し、その旨をログに出す。USB を抜いた場合は未接続に戻り、ログに「[INFO] シリアル: 未接続(デバイスが外れた(USB の抜去など))」を 1 行だけ出す(抜去は普通の切断なので警告にしない。ほかの読み取りエラーで切れたときは WARN で理由を出す。接続が続く読み取りエラー(バッファあふれ等)は WARN で「読み取りエラー」を出して読み続ける)
6. 接続から 3 秒たってもメッセージが来ない場合は、ログに注意を出す(ファームウェアがテキスト表示のまま、またはセンサーの初期化に失敗して止まっている。[frame-format.md](frame-format.md) の「モードの切り替え」)

### 画面

- **距離**: 有効なゾーンは近 = 赤 → 黄 → 緑 → 遠 = 青(0〜2000 mm。Step 2 のターミナル表示と同じ考え方で、段階ではなく連続の色)。2000 mm 超は暗い紫。無効なゾーンは灰色の濃淡で、記号 `x` = ステータスが 5 / 9 以外、`?` = sigma が 50 mm 超、記号なし = ターゲットなし(判定の順も Step 2 と同じ)。「距離の数値」で有効なゾーンに mm の値を重ねる
- **signal_per_spad(IR 画像)**: グレースケール(黒 = 弱い、白 = 強い)。値の幅が広いので対数スケールで、範囲はフレームの最小・最大(0 を除く)に自動で追従する(広がるときはすぐ、狭まるときはゆっくり)。無効なゾーンも値のまま描く
- **nb_spads_enabled**: 青の濃淡(暗い = 少ない、明るい = 多い)。線形・自動レンジ
- 各画像の下に単位と凡例(色の帯と範囲)。T が 2 以上のフレームは最初のターゲットを描く
- 画像にマウスを乗せると、カーソルのそばのツールチップに、そのゾーンの全フィールド(全ターゲットの距離・ステータス・sigma・signal、ターゲット数、SPAD 数)を出す。乗せたゾーンは、ほかの図(2D 画像・レクチャー A / B の画像・LiDAR 風ビューとレクチャー C の扇形)でも白い枠で示す。ツールチップは画面の右端・下端でははみ出さないよう左・上に反転し、全画面でも出る。マウスが図から出たら消える(タッチ操作には対応していない)。対象の図の一覧は下の「ゾーンの値(マウスを乗せる)」の欄と、「最終デモ(Step 5)」に書いた
- 「受信」の欄: 受信 fps(ブラウザが受け取った頻度)、送信側 fps(タイムスタンプの間隔から)、種別ごとの受信数、seq の欠落(回数と個数)・後退、測距フレームの間隔の異常(状態メッセージの頻度から求めた周期の 1.5 倍超。センサー側の取りこぼしは seq に現れないのでこれで見る)、理由別の拒否の数、捨てたバイト数、温度
- 「状態メッセージ」の欄: ファームウェアの版、解像度、field_mask、測距の頻度、反転、I2C クロック、1 フレームの読み出しバイト数
- 「ログ」の欄: ファームウェアのログ(種別 2)と、ブラウザ側の出来事(接続・エラー)。最新 200 件。接続すると、状態メッセージの後にファームウェアから測距の設定の 1 行(`sensor: ...`。起動ログと同じ)が届く

### 記録ファイルの再生

`tools/capture_serial.py` で保存したファイル(USB シリアルの生のバイト列)を「記録ファイルの再生」で選び、「再生」を押す。実機なしで表示を確かめられる。

- 時間: 「記録時のタイムスタンプ」はメッセージの timestamp_us の間隔で流す(記録ファイルには受信時刻が入っていないため。間隔は 1 秒で頭打ち、時刻が戻ったところは待たない)。「一定(15 fps)」は測距フレームを 66.7 ms ごとに流す
- 速度(0.25〜4 倍)と繰り返しを選べる(再読み込みでブラウザがフォームの値を復元した場合も、起動時と再生の開始時に画面の値を読み直す)。接続中は再生できない。再生中に「接続」を押すと再生を止める
- 再生は実機と同じ受信処理(0x00 区切り → COBS → CRC → 形式の検査 → 統計)を通る
- 繰り返すときは、周の継ぎ目で受信処理・統計・表示をリセットし、新しいデータ源として始め直す(リセットしないと、前の周の末尾と次の周の先頭のテキストが 1 つのパケットとしてつながって拒否され、seq も後退として数えられる)。統計は周ごとの値になる

### 3D 点群(Step 4)

2D 画像の下の「3D 点群」に、最新の測距フレームを 3D で描く。接続中も記録ファイルの再生中も同じように動く。

- **座標**: センサーから外を見た向き。赤の軸 = x(センサーから見て右)、緑 = y(上)、青 = 前方。センサーは原点の小さな箱
- **2D 画像との左右の違い**: 2D 画像は「センサーを正面から見た図」(9 ピン列を左にして持つと zone 0 が右上)。3D はセンサーの側から外を見るので、左右が逆に見える。2D の右上にある zone 0 は、3D では左上(x < 0、y > 0)にある。反転(h / v)は 2D と同じ設定を使うので、2D が正面から見た見た目と一致していれば 3D も実物と一致する。逆に、3D の見た目を 2D に揃えようとして h を切り替えると、2D も 3D も実物と合わなくなる(左右が逆に見えるのは正しい状態)
- **距離の解釈**: 「垂直距離」(センサー面からの距離。z = d)と「半径」(視線方向の距離。原点からの長さ = d)を切り替える。**実機では垂直距離が正しかった**(正面の壁が垂直距離で平面になった。2026-09-27)。既定は垂直距離。「半径」は比較の学習用
- **表示**: 「点」はゾーンの中心に 1 点。「ゾーンの広がり」は、各ゾーンが受け持つ四角錐を、そのゾーンの距離で切った四角形(遠いほど大きい)。隣のゾーンと同じ距離なら隙間なく接するので、8x8 の粗さがそのまま見える
- **色**: 距離 / signal_per_spad / nb_spads_enabled。色の付け方は 2D 画像と同じ(signal と SPAD 数の自動レンジも 2D と共通)
- **無効ゾーン**: 既定では描かない。「無効ゾーンも表示」で半透明の灰色で描く(距離が 0 以下のゾーンは描かない)
- **目安**: 灰色の四角錐は視野(各軸 45°、4 m まで)。床のグリッドと前方の半円の輪は 0.5 m ごと。床の高さはセンサーの 0.5 m 下と仮定した目安で、実際の床ではない
- **操作**: 左ドラッグで回転、ホイールでズーム、右ドラッグで移動。3D ビューの上ではホイールがズームになり、ページはスクロールしない。「視点をリセット」でセンサーの右後ろ上から前方を見る位置に戻す
- 描画は、データ・向き・3D の設定・カメラのどれかが変わったときだけ行う
- WebGL のコンテキストが失われた(GPU のリセット等)ときは、3D の注記とログに出し、復帰したら描き直す
- WebGL が使えない環境では、3D の欄に理由を出し、2D の表示は続ける

**幾何の仮定**(`web/src/geometry.ts`。ST の資料では確かめていない):

- 画角は各軸 45°(水平・垂直とも ±22.5°)を採用。8x8 のゾーンのピッチは 5.625°、4x4 は 11.25°。ST / Pololu の公称は「45° × 45°、対角 65°」だが、このモデル(方向 (tan θx, tan θy, 1))では対角は約 60.7° になり、公称の対角 65° と同時には成り立たない。画角の定義(各軸の値か、どこで測った値か)は未確認で、値は各軸 45° のままにしている
- ゾーンの中心は**角度で等間隔**と仮定。隅のゾーンの中心は ±(22.5° − 2.8125°)= ±19.6875°。tan で等間隔(平面上で等間隔)の可能性もあるが、8x8 の粗さでは実験での判別が難しい
- 距離は垂直距離(2026-09-27、正面の壁で確認。ULD の changelog の "rad2perp coefficients" とも合う)。同じ垂直距離に対する半径は、点の表示の隅のゾーンの中心(±19.6875°)で約 1.121 倍(差 約 12%)、パッチの外周の角(視野の隅、±22.5°)で約 1.159 倍(差 約 16%)
- 各ゾーンの最初のターゲット(t = 0)を使う

### 最終デモ(Step 5)

LiDAR 風ビュー・レクチャー画面・プレゼン用の全画面・実機なしのデモを足した。どれも接続中・記録ファイルの再生中・デモの再生中に同じように動く。

**LiDAR 風ビュー**(ページの先頭。真上から見た図):

- センサーは下の中央、上が前方、右がセンサーから見て右。視野(±22.5°)の扇に、0.5 m ごとの距離の輪と角度の目盛り(0°、±11.25°、±22.5°)
- 点: 全ゾーンの有効な点を距離の色で暗く。距離は垂直距離(Step 4 で確認)
- スキャン線(明るい水色): センサーから見た列ごとに、選んだ行の帯の有効ゾーンの最近距離をつないだ線(2D LiDAR の 1 回転ぶんに相当)。帯は「中央 2 行(水平面の断面)」(既定)か「全行」
- 残像: 直近 1.5 秒のスキャン線を、古いほど薄く(持つのは最大 64 本。LiDAR 風ビューが見えていない間も増え続けない)
- 動いたゾーンの強調(橙): ゾーンごとに距離の遅い移動平均(背景。1 フレームで差の 5% 追従)を持ち、背景との差が max(100 mm, 3 × sigma) を超えたゾーン。止まった物は 2 秒ほどで背景になる(差 400 mm なら 28 フレーム)。値は暫定で、記録を使って調整する
  - ターゲットなし(ステータス 255 またはターゲット数 0)のゾーンは、背景を「空」として持つ。空のゾーンに物が入ったら、差によらず「動いた」とし、背景は 4 m(最大測距距離)から追従し始める(1 m の物なら約 4.5 秒、67 フレームのあいだ強調が続く)。物が去って空に戻ったら背景も空に戻すので、同じ距離を再び通っても検出できる
  - ステータスが無効・sigma の上限超えのゾーンは判定せず、背景も変えない
- 「走査の演出」: 扇の中を往復する線を出す。**このセンサーは走査していない(全ゾーン同時に測るフラッシュ型)ので、線は見た目の演出**。出している間は画面にそう書き、図の左上に「演出あり」と出す
- 最大距離(2 / 3 / 4 m)を選べる

**レクチャー画面**(A / B / C の 3 パネル。解説文は `web/src/lecture/text.ts` にまとめてあり、文言はそこだけ直せばよい):

- A. 返りの強さと受光側の調整: IR 画像(signal_per_spad)と SPAD 数の画像を並べる
- B. 全ゾーン同時(フラッシュ型)と走査型: このセンサーの実際の距離画像と、**走査型の模擬**(センサーから見て左端の列(図では右端)を 7 フレーム前、右端の列(図では左端)を最新のフレームから取った合成。8x8 のとき)を並べる。模擬の図には「模擬」と書く。8 フレームたまるまでと、解像度などが変わった直後は「フレーム待ち」。手を横に振ると模擬の図だけ像がゆがむ(2026-09-27 に実機で確認)
- C. 垂直距離と半径: 同じデータを、垂直距離として置いた真上からの図と、半径として置いた図で並べる
- 業務の LiDAR は一般的な方式(ラインレーザをミラーで走査する方式、パイロットパルスで出力を決める方式)として書き、製品名などは書いていない。このセンサーについては、実機で確認したことと確認していないことを分けて書いている

**ビューとプレゼン(全画面)**:

- ビューは 6 つ: `1` LiDAR 風ビュー、`2` 3D 点群、`3` 2D 画像、`4` レクチャー A、`5` レクチャー B、`6` レクチャー C
- 「全画面(F)」ボタンか `F` キーで、選んだビューだけを画面いっぱいに出す(Fullscreen API)。操作パネル・統計・ログは隠れる。`1`〜`6` でビューを切り替え、`Esc`(または `F`)で戻る。画面の大きさが変わると描き直す
- 通常の表示で `1`〜`6` を押すと、そのビューまでスクロールする
- キーは、テキスト入力欄・選択肢(select)にフォーカスがあるとき、Ctrl / Alt / Meta と一緒のとき、押しっぱなしの繰り返しでは効かない。プレゼンのビューの選択肢は、選んだ後にフォーカスを外すのでそのままキーが効く。ほかの select を操作した後は、ページの余白をクリックしてから押す
- URL のパラメータで開ける: `?view=lidar`(ビュー。`lidar` / `3d` / `images` / `lectureA` / `lectureB` / `lectureC`)、`?demo=step3-sample`(デモをループ再生)。例 `http://localhost:5173/?view=lectureB&demo=step3-sample`。ビューを指定すると、そのビューだけを大きく出した表示で開く(ブラウザの制約で、ユーザーの操作なしには全画面にできないので、全画面にするには `F` を押す)。デモだけを指定したときは、デモの推奨ビューに切り替える(ビューも指定したときはそちらを優先)

**ゾーンの値のツールチップ**(マウスを乗せる):

- 対象: 2D 画像 3 枚、レクチャー A の 2 枚、レクチャー B の 2 枚(カーソルの下のゾーン)、LiDAR 風ビューとレクチャー C の 2 枚(カーソルに最も近い点、12 px 以内。描いている有効な点だけ)。3D 点群は対象外
- 出すもの: どの図か、そのゾーンの全フィールド。レクチャー B の模擬の図では「この列は N フレーム前の値(seq …)」、扇形では真上から見た位置(右・前方 [mm])と、垂直距離 / 半径のどちらとして置いた図か、LiDAR 風ビューでは「背景から動いた」かも出す
- 乗せたゾーンは、ほかの図でも白い枠(扇形では白い輪)で示す。向きやデータが変わっても、乗せている位置から毎回求め直す
- 以前の「ゾーン」の欄は、対象の図の一覧と使い方の説明に置き換えた

**デモ(実機なし)**:

- 「デモ」のメニューで選んで「ループ再生」を押す。記録ファイルの再生と同じ仕組み(記録時のタイムスタンプ、繰り返し)で、選んだデモの推奨ビューに切り替える。接続中は再生できない
- **デモ用記録の収録は保留**(収録に向いた場所で後日)。いまは仮のデモとして、Step 3 の動作確認の記録(`step3_cap_20260927.bin`、6 秒、85886 バイト)を 1 件だけ登録している。収録したら差し替える
- 形式: `web/public/demos/` に記録ファイル(`tools/capture_serial.py` の出力そのまま)と一覧 `manifest.json` を置く。一覧は起動時に読み、形を検査する(誤りがあればログに理由を出し、メニューは使えないままにする)
